# 系统架构

## 当前检索链路

```text
PDF / Markdown / TXT
          |
     解析与切块
          |
   +------+------+
   |             |
哈希向量索引   BM25 关键词索引
   |             |
   +------v------+
       RRF 融合
          |
   查询词覆盖率重排
          +--------------------+
          |                    |
POST /api/v1/search     证据句选择与拒答
          |                    |
   可追溯文本块          引用候选合法性校验
                               |
                    POST /api/v1/answers
                               |
                  带 [S1] 引用与安全提示的回答
```

`POST /api/v1/documents/upload` 会把同一批新文本块写入两个底层索引；搜索接口通过统一的 `SearchIndex` 抽象使用混合检索器，因此路由不依赖具体实现。`RagAnswerService` 负责检索与回答生成编排，并拒绝生成器引用不在本次候选集中的文本块。

## 当前 Agent 请求流程

```text
POST /api/v1/agent/runs
            |
确定性策略 Agent（最多三步）
   |--------+--------------------+
   |        |                    |
知识检索   故障历史查询         传感器区间分析
   |        |                    |
RAG 回答   只读 JSON 演示数据    用户提供的上下限
   |
摘录生成器或显式配置的 Responses API
            |
回答 + 已校验引用 + 工具轨迹 + 停止原因 + 安全提示
```

当前 Agent 不让模型自由选择和无限调用工具。工具集合与执行顺序由服务端策略控制，外部输入经过 Pydantic 校验，所有工具均为只读操作。

## 关键技术取舍

1. **分离 API、领域服务和基础设施**：路由只处理 HTTP；检索和 Agent 逻辑放入服务层；模型、向量数据库和关系型数据库连接放入基础设施层。
2. **从导入阶段保留引用信息**：文档和文本块从一开始就保存来源、页码、章节和稳定 ID，避免回答生成时无法追溯证据。
3. **工具必须能够独立测试**：检索、故障查询和传感器分析不依赖 Agent 才能运行。
4. **Agent 必须有边界**：工具使用白名单，最多执行三步，并返回 `stopped_reason`，不使用无限自主循环。
5. **安全操作由人确认**：系统只提供建议，不直接控制真实设备。
6. **先保证离线可复现**：当前哈希向量只用于验证链路和建立基线；真实语义质量必须在接入 Embedding 模型并扩充评测集后重新测量。

## 计划采用的技术

- API 与数据验证：FastAPI、Pydantic
- 关系型数据：当前 JSON 演示，计划迁移 PostgreSQL
- 向量与关键词检索：Qdrant、稠密向量与稀疏表示
- 大模型访问：OpenAI Responses API，可通过配置切换回离线摘录器
- 演示界面：Streamlit
- 工程化：uv、Pytest、Ruff、Docker、结构化日志
